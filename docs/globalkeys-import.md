# Раздел «Ключи»: ручные записи и автоматический импорт

Mihomo/Clash YAML никогда не меняется этим разделом. `globalkeys_response_type()` в
`lib/globalkeys.php` проверяет фактическое тело и Content-Type перед любой
инъекцией. То же условие проверяется в `index.php` после штатных правил доступа.
Существующий конвейер Mihomo, дополнительные конфиги Squad и AddSub не изменены.

## Ручные ключи

В админке откройте «Ключи». Каждый элемент можно развернуть кнопкой
«Редактировать», проверить синтаксис и сохранить. Редактор сохраняет полный
исходный Xray JSON целиком. Изменение записи другим администратором приведёт к
отказу сохранения; обновите страницу и повторите правку. Название, исходный
текст и разобранная форма меняются одной
транзакцией.

Ручные VLESS URI попадают в поддерживаемые Xray JSON, plain text URI и base64 URI подписки.
Полные Xray профили добавляются только в массив полных Xray профилей. JSON
объекты, sing-box, HTML, неизвестные форматы и любой YAML проходят без изменений.

## Автоматический импорт

1. Добавьте до 20 публичных HTTPS источников на вкладке. Локальные адреса,
   небезопасный DNS, нестандартные порты и редиректы запрещены. Источник
   ограничен 2 МБ и 15 секундами загрузки; обрабатываются первые 2000 URI.
2. Настройте интервал, проверочный URL и код, тайм-аут, повторы и политику
   частичного успеха. Включите сбор. «Собрать сейчас» только ставит отметку
   для фонового worker и не замедляет запрос подписки.
3. После успешной сборки включите публикацию. По умолчанию она выключена.
   Снимок старше заданного срока игнорируется. При ошибке источников предыдущий
   корректный снимок остаётся на месте.

Автоматический пул хранится отдельно от `global_keys`. Из поставленного
`MihomoKeysGenerator` адаптированы `parsers.py` и `xray_subscription.py`
для извлечения plain/base64 URI и Xray JSON, нормализации и проверки формата.
Его загрузчик и генерация выходного Mihomo YAML не используются. Оригинальный
парсер не поддерживает YAML *на входе*, поэтому `globalkey_adapter.py` отдельно
считывает из YAML только VLESS узлы раздела `proxies`; остальные поля игнорируются.
Исходный проект не содержал файла лицензии — при дальнейшем распространении
адаптированных модулей уточните лицензионные условия у владельца исходников.

Для публикации пока поддержан только VLESS, совместимый с имеющимся
`vless_to_xray()` и URI выдачей. VMess, Trojan, Shadowsocks, Hysteria2,
неэквивалентные транспорты и узлы с потерей параметров исключаются и
показываются в результатах как `unsupported_for_target` или `invalid`.
Совпадение имени не делает разные подключения дубликатами. Имена для выдачи
становятся уникальными и стабильными.

Статус `working` означает, что проверочный HTTP запрос получил ожидаемый код
через SOCKS вход отдельного локального Xray-core с проверяемым VLESS outbound.
Открытый TCP порт узла не считается успехом. Если Xray отсутствует, статус
`not_checked` и публикация запрещена, пока администратор явно не разрешит
непроверенные ключи. По умолчанию проверки запускаются параллельно по восемь,
с общим дедлайном 600 секунд. TLS сертификат проверяется. Для собственного
доверенного CA можно задать `GLOBALKEY_CHECK_CA_FILE` с путём к PEM. Секретные URL,
URI и конфиги не выводятся в журнал запусков. Сохранённые записи доступны
администратору БД и редактору источников; защитите доступ к БД и `data/`.
После заданного числа неудачных циклов (по умолчанию двух) узел исключается.
Если у всех узлов достигнут этот порог, публикуется пустой автоматический пул;
штатная подписка панели остаётся целой. Отсутствие Xray не считается таким
порогом и сохраняет предыдущий снимок до истечения его срока.

## Xray JSON шаблон

Необязательный шаблон представляет собой *полный Xray JSON объект*. В
`outbounds` нужен один маркер `{"tag":"globalkeys_insert"}`. Вместо маркера
вставляются проверенные VLESS outbounds. Остальные секции объекта сохраняются
без изменения. Ссылки на маркер в других секциях запрещены: шаблон не
сохраняется. Результирующий профиль добавляется только к Xray ответу,
представленному массивом полных профилей. При одиночном Xray JSON объекте
применяется штатная вставка outbounds. URI подписка шаблон не получает.
В разделе результатов администратор может скачать черновой список URI и
собранный Xray JSON профиль из последнего снимка, включая выключенную
публикацию. Скачивание не меняет клиентские подписки.

## База данных и запуск

SQLite и MySQL/MariaDB получают четыре таблицы при первом обращении к разделу
или запуске worker: `globalkey_import_sources`, `globalkey_import_nodes`,
`globalkey_import_builds`, `globalkey_import_runs`. Ручная таблица `global_keys`
не меняется. Настройки лежат в существующей `settings`. При переносе БД новые
таблицы создаются в приёмнике и копируются. Перед обновлением сохраните резервную
копию БД; затем обновите код/образ и откройте вкладку или запустите worker.
Журнал и старые сборки удаляются после 30 дней; последний снимок сохраняется.

Docker образ содержит Python/PyYAML и закреплённый Xray-core для amd64.
`docker/entrypoint.sh` запускает worker как `www-data` рядом с PHP-FPM и nginx.
На VPS `install.sh` устанавливает Python/PyYAML, Xray для x86_64 и включает
`submw-globalkeys.service`. Другую архитектуру можно подключить через
`GLOBALKEY_XRAY_BIN=/absolute/path/to/xray`. Ручной CLI запуск:

```sh
php tools/globalkeys_worker.php
```

Для shared hosting, где есть CLI PHP и Python/PyYAML, настройте cron на
`php /path/to/tools/globalkeys_worker.php` не чаще раза в 5 минут. Для
непрерывного процесса используйте `--daemon`. Пользователь worker должен
иметь права на БД и `data/`; одновременные запуски исключаются файловой
блокировкой.

## Проверки

```sh
php -d extension=pdo_sqlite -d extension=mbstring tests/globalkeys_regression.php
php tests/globalkeys_adapter_integration.php
python3 -m unittest discover -s tests -p test_globalkey_adapter.py -v
```

Ограничения текущей реализации: тест одного источника проверяет загрузку и
разбор, но не проверяет каждый его узел через ядро; для этого нужна полная
сборка. При 304 и включённом разделе «Ключи» middleware запрашивает полное
тело для определения формата. Mihomo/Clash и неизвестные ответы сохраняют
исходные 304 и заголовки; поддерживаемые не-Mihomo ответы получают обновлённый
полный ответ.
